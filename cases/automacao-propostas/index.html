Extração Estruturada de Dados de Apólices com n8n e IA

Workflow operacional que recebe PDFs fictícios de apólices, sanitiza duplicidades, usa IA para estruturar informações, valida campos críticos e grava dados limpos em planilha.

O Problema Operacional

Em processos administrativos envolvendo corretagem ou análise de seguros, o recebimento de apólices e propostas em formato PDF exige digitação manual exaustiva. Esse modelo gera diversos problemas comuns:

Gargalo de tempo: Colaboradores gastavam minutos digitando dados que já estavam no documento original.

Erro de digitação: Risco frequente de digitação errada em campos como CPF/CNPJ, placas de veículos, datas de vigência e prêmios líquidos.

Desperdício de API: Processar arquivos repetidos ou re-enviar propostas duplicadas para processamento de IA eleva custos de API sem necessidade.

A Solução Desenvolvida

Foi desenvolvida uma esteira automatizada utilizando o n8n que orquestra a captura, validação, extração inteligente e gravação segura dos dados sem qualquer digitação manual.

O fluxo segue etapas lógicas blindadas contra exceções:

  1. Captura e Gatilho: O n8n monitora uma pasta específica no Google Drive. Assim que um arquivo PDF novo é adicionado, a execução inicia.
  2. Verificação de Duplicidade: A deduplicação consulta a planilha usando drive_file_id antes da etapa de IA. Se o arquivo já estiver registrado, ele é enviado para a pasta de Duplicados e não passa por extração, IA ou gravação duplicada.
  3. Extração de Texto: O conteúdo de texto bruto é extraído do PDF.
  4. Estruturação por LLM (IA): O texto extraído é encaminhado à API do modelo de linguagem (OpenAI Chat Model) com um prompt estrito de extração em JSON estruturado (Structured Output). A IA devolve apenas os campos mapeados (ex: Nome Segurado, CPF fictício, Placa, Vigência, Coberturas, Valor).
  5. Normalização e Escrita: Um Code Node normaliza datas para padrão brasileiro (DD/MM/AAAA) e valores monetários para float. Em seguida, atualiza a linha na planilha de controle do Sheets.
  6. Organização de Arquivos: O arquivo original é movido para uma pasta de /Processados ou, em caso de falha de extração, para a pasta de /Erros.
