Organizador Financeiro Inteligente

Projeto autoral ativo de controle financeiro pessoal, projetado para garantir máxima privacidade de dados, estruturação relacional e importação assistida de extratos.

Status: Projeto em Desenvolvimento Ativo

Este é um projeto pessoal em andamento, construído sob a premissa de desenvolvimento incremental. As seções a seguir detalham a arquitetura técnica já modelada, a sanitização de dados e os recursos de importação local implementados, sem promessas de funcionalidades não construídas.

O Problema Operacional

A maioria das aplicações de controle financeiro no mercado exige a sincronização automática de contas bancárias por meio de APIs de terceiros. Isso acarreta duas dores principais:

Exposição de Dados Sensíveis: Compartilhar credenciais bancárias e dados de transações com empresas privadas eleva o risco de vazamentos e violações de privacidade.

Inconsistência de Múltiplos Extratos: Importar manualmente extratos de diferentes bancos (com colunas e formatações distintas) gera duplicidades e exige digitação corretiva constante.

Falta de Autonomia Lógica: Sistemas fechados limitam o controle do usuário sobre regras específicas de categorização de despesas e planejamento de provisões fixas.

A Solução Desenvolvida (Premissas e Estrutura)

Foi desenhado e está sob **desenvolvimento incremental** um Organizador Financeiro Privado que elimina a necessidade de integração direta com bancos. A aplicação está planejada para operar de forma local e assíncrona, consumindo arquivos de extratos em formato CSV exportados de forma segura pelo próprio usuário.

A arquitetura baseia-se nos seguintes pilares técnicos, projetados para etapas incrementais:

  1. Privacidade por Padrão (Premissa): Armazenamento em banco de dados local. Toda a lógica de processamento e consolidação de despesas está planejada para rodar inteiramente no ambiente do próprio usuário, sem conexões externas ou tráfego de dados para servidores terceiros.
  2. Importador Estruturado Local (Em Validação): Lógica em JavaScript para ler arquivos CSV locais, sanitizar campos de data e valores e descartar transações duplicadas de forma assistida.
  3. Categorização Lógica (Planejado): Mecanismo de mapeamento relacional projetado para agrupar despesas com base em palavras-chave configuradas pelo usuário.
  4. Desenvolvimento Incremental: O primeiro ciclo concentrou-se no estudo de modelagem relacional de tabelas de contas, categorias e transações, seguido pelo rascunho de scripts locais de sanitização de CSVs brutos, com validações no console.

Políticas de Segurança e Confidencialidade

Nota de Segurança Estrita: Este portfólio não armazena nem gerencia dados financeiros reais do desenvolvedor ou de terceiros. Toda modelagem apresentada utiliza bancos de dados mockados com dados de teste. A aplicação não faz conexões remotas não auditadas de envio de informações.
